# ARK Design — AI室内设计辩论引擎

## Project Overview

ARK Design is an AI-powered interior design debate engine that simulates multi-expert design debates and generates complete proposal deliverables (PPT HTML + speech scripts). Built for "李老师设计工作室" (Li's Design Studio).

**Key concept**: 4 specialized AI agents debate a design project, a "narrative architect" synthesizes their output into a 4-act story, then the system generates a presentation and speech script.

## CLI Usage

```bash
# Configuration (stores to ~/.arkconfig.json)
node ark.js config --key sk-xxxxx --provider deepseek

# Run a full project (debate + PPT + speech)
node ark.js all --name "项目名" --type residential --budget 80万

# Available space types: residential | restaurant | hotel | exhibition | retail

# Individual commands
node ark.js debate --name "项目名" --type hotel --budget 200万 --city 大理
node ark.js ppt <project-dir> --theme 沙丘        # themes: 沙丘/墨水经典/靛蓝瓷/森林墨/牛皮纸
node ark.js speech <project-dir>                   # with --no-ai to skip AI polish
node ark.js render <project-dir>                   # AI image generation (needs GRSAI_API_KEY env)

# PPT Knowledge Learner (Python)
python ppt_learner.py                              # scan new files in ppt/
python ppt_learner.py --all                        # reprocess all
python ppt_learner.py --watch                      # watch mode
```

Supported API providers: deepseek, openai, qwen, zhipu, doubao, grsai

## Architecture

### CLI Layer (`lib/`)
| File | Role |
|---|---|
| `ark.js` | CLI entry — 6 commands: config/debate/ppt/speech/render/all |
| `lib/config.js` | Config read/write to `~/.arkconfig.json` |
| `lib/api.js` | Streaming + non-streaming API client; `PROVIDER_PRESETS` for 6 providers; SSE parsing |
| `lib/engine.js` | Debate engine — runs 4 agents sequentially, then generates narrative/pages |
| `lib/ppt.js` | PPT generator — reads template.html, injects theme + 8 slides |
| `lib/speech.js` | Speech generator — AI (via `speech-system.md`/`speech-user.md` prompts) or template-based |
| `lib/render.js` | AI image generation via GrsAI draw API, replaces placeholders in proposal.html |
| `lib/prompt-loader.js` | Loads `.md` prompts from `prompts/` with `{{VAR}}` substitution |

### Debate Engine (`lib/engine.js`)
4 agents run sequentially (order varies by space type):
1. **visual-expert** (审美专家) — design concepts, materials, mood
2. **construction-mgr** (硬核执行官) — feasibility, risk assessment
3. **cost-controller** (精算专家) — budget allocation, ROI
4. **virtual-client** (虚拟客户) — stress-test, objections
+ **Narrator** (叙事架构师) — synthesizes into 4-act narrative, outputs JSON page definitions

Debate order per type:
- residential: visual → construction → cost → client
- restaurant: construction → cost → visual → client
- hotel: visual → construction → cost → client
- exhibition: visual → cost → construction → client
- retail: cost → visual → construction → client

Page count limits (min–max): residential 35–50, restaurant 40–55, hotel 45–62, exhibition 35–50, retail 35–45.

### Prompt System (`prompts/`)
33 `.md` files, loaded via `prompt-loader.js`. Each agent has a base prompt + 5 type-specific variants. Conditional files load based on project context:

- **Base + type**: `visual-expert.md` + `visual-expert-{type}.md`, same pattern for construction-mgr, cost-controller
- **Conditional**: `region-rules.md` (when city/region set), `cost-controller-funding.md` (when funding phases exist), `cost-controller-region.md` (when city set), `cost-controller-commercial.md` (when non-residential)
- **Speech**: `speech-system.md` (system prompt) + `speech-user.md` (user prompt with 13 `{{PLACEHOLDER}}` vars)
- **Narrator**: `narrator-{type}.md` (5 files)

When editing prompts: preserve all `{{PLACEHOLDER}}` variables — the engine substitutes them at runtime.

### PPT Knowledge Base (`.ppt-knowledge/`)
Auto-generated design knowledge from real design PPT files. Generated by `ppt_learner.py` (6-layer analysis: text → images → text-image relations → narrative → concept → patterns).

Each project directory contains: `project.json`, `result.json`, `debate.log`, `proposal.html`, `speech.md`, `images/` (after render).

## Technical Notes

- **Environment**: Node.js CLI + static HTML frontend (no framework). Python 3 for ppt_learner.
- **Config**: API key stored in `~/.arkconfig.json` (also supports provider/model/url).
- **API**: All providers use OpenAI-compatible `/v1/chat/completions` (zhipu uses `/v4/`). SSE streaming via `api.stream()`, non-streaming via `api.call()`.
- **PPT Template**: `lib/template.html` — single-file HTML/CSS/JS, e-ink magazine style with 5 color themes.
- **Image rendering**: `render.js` uses GrsAI draw API (`gpt-image-2` model), requires `GRSAI_API_KEY` env var.
- **PPT learner**: Requires `python-pptx` (`pip install python-pptx`). Uses file size+mtime fingerprints for incremental processing.
- **Gemini models**: When using GrsAI's `gemini-3.1-pro`, responses may include reasoning tags that need stripping from prompt files.
